## One engine, several interfaces

OrbProp runs the same C++ propagator from the command line, a C API, and a Python package. The desktop workbench adds mission configuration, plots, a timeline, and 3D trajectory views. Batch experiments and interactive sessions share the numerical core.

## Physics and application code

Force models and integrators have separate responsibilities. A method registry connects the selected gravity, atmosphere, radiation, tides, and ephemerides to the configuration of each run. Results include the resolved methods, units, and reference frames.

The application displays those results alongside spacecraft and mission parameters. It keeps simulation state separate from camera and display state.

## Working with other tools

Trajectory exchange includes CCSDS documents, CSV, HDF5, CZML, and SPICE kernels. The C and Python interfaces let scripts use the engine without depending on the desktop application.

The spacecraft image simulator combines an astrometric chain with optics and detector noise, producing FITS images and catalogue references. This connects orbital motion to the image a camera would observe.
